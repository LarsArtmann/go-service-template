## Verdict

Used SUPERBLY in shape and to the max the current preset allows: every template binary links go-sse twice-over without a single template import (the always-on health dashboard's live view at `GET /health/sse`, and the `APPKIT_REALTIME=on` leg at `GET /events`), and `go mod why -m github.com/larsartmann/go-sse` resolves `internal/app → preset → realtime → go-sse`, i.e. fully mediated. The library's deliberate non-goal (no `Broadcaster.ServeSSE`, no handler opinions, README "What's NOT Included") is precisely why the template needs no SSE code, so "thin composition root" and "max utilization" coincide here. What keeps it from very high is upstream, not template-local: the preset's realtime leg cannot configure the hub (no store, so reconnection replay, go-sse's flagship feature, is structurally absent for env-flag adopters), `sse.Replay`'s `(int, error)` return forced appkit to reimplement the replay loop for exactly-once dedup, the v0.6.2 pin predates the exported `DefaultSubscriberBuffer`, and the default 30s `WriteTimeout` cuts every mediated stream (independently verified below; agrees with `docs/review/libs/go-appkit.md` Gaps #6).

## Gaps and opportunities

1. **Default `WriteTimeout: 30s` kills every mediated SSE stream (independently verified from the go-sse side; agrees with go-appkit.md Gaps #6 and Risks).** go-sse documents proxy survival (`README.md:73-83` heartbeat vs Nginx/Cloudflare/ALB idle timers) but says nothing about `http.Server.WriteTimeout`: no sentinel (it cannot own the server), no "server requirements" note, and its examples run under bare `http.ListenAndServe` (`example/server.go:43`, i.e. zero write timeout), so the trap is invisible in everything the library ships. Heartbeats do not help: they reset proxy idle timers, not `http.Server` deadlines. The mitigations all live in go-appkit: the `NoTimeout` sentinel (`go-appkit/config.go:23-30`), the README SSE section (`go-appkit/README.md:452-467`), the Timeout-middleware skip (`middleware.go:42-43`), and, critically for THIS template, `go-appkit/health/doc.go:124-129` already documents that the dashboard's own `GET /health/sse` (spine, always-on) "degrades but works" under the default 30s. Template today: `internal/app/service.go` leaves `Timeouts` zero, so the default binary ships 30s-capped dashboard streams, and `APPKIT_REALTIME=on` produces 30s-dying `/events` streams. Impact: high (the documented env flag is a footgun; the spine degrades silently). Fix: preset applies `NoTimeout` when the realtime leg resolves on (or README documents the pairing) `[PRESET-UPSTREAM]`; go-sse adds a "Server requirements" paragraph naming write deadlines as the caller's job `[LIB-UPSTREAM]`. The template itself should not hardcode `NoTimeout` (that would disable the deadline for all non-SSE routes too; it is the preset's composition decision).
2. **Preset realtime leg cannot configure the hub, so reconnection replay is structurally absent for env-flag adopters.** go-sse's flagship feature pair (`Last-Event-ID` + `EventStore` replay, README:85-111, guides `docs/guides/reconnection-and-retry.md`) is fully implemented in the mediator (`realtime/handler.go:193-247`) but unreachable: `mountRealtime` calls bare `realtime.NewHub()` (`preset/preset.go:195`) and `RealtimeConfig` only passes handler-side `MountOption`s (`preset/config.go:137-138`); there is no `WithStore`/`WithBufferSize`/hub-options passthrough (they exist: `realtime/hub.go:73-98`). Impact: every adopter who flips `APPKIT_REALTIME=on` gets fan-out where dropped events are lost until the next broadcast, with no reconnect recovery. Sketch: `type RealtimeConfig struct { ...; HubOptions []realtime.Option }` → `realtime.NewHub(cfg.Realtime.HubOptions...)` in `mountRealtime`. `[PRESET-UPSTREAM]`
3. **`sse.Replay` returns `(int, error)`, forcing mediators to reimplement the loop.** appkit's handler needs the replayed IDs for subscribe-before-replay dedup (exactly-once delivery), so it hand-rolls the store-read + send + ID-collect loop (`realtime/handler.go:193-247`) instead of calling `sse.Replay` (`replay.go:40-79`). Every future fleet mediator faces the same choice. Fix: return the replayed events (or IDs) from `Replay`/`ReplayFiltered`, or accept a per-event callback. `[LIB-UPSTREAM]`
4. **Hub health is one line from the preset's probe and unwired.** `Hub.Health()` returns a `BroadcasterHealth` snapshot designed for health endpoints (`realtime/hub.go:143-145`, `fanout_lifecycle.go:113`), and the preset already owns a probe (`preset/preset.go:109`). A `realtime` check (or subscriber-count metric) when the leg is on would make stream health observable fleet-wide. `[PRESET-UPSTREAM]` (low impact × high ease, hence ranked last of the wiring items)
5. **v0.7.0 drift is real but not the template's to fix** (detail in Version currency): `DefaultSubscriberBuffer` (CHANGELOG [0.7.0] Added, resolves appkit's own `hub.go:77-83` "cite the constant instead" note) lands the moment appkit bumps. No template action. `[NOT-NOW: rides the next appkit refresh train, which go-appkit.md Gaps #1 already routes as [TEMPLATE]; a template-side `go get go-sse@v0.7.0` would pin ahead of every mediator for zero functional gain]`

## Should the archetype adopt or wire more?

No new template code. The honest routing of the "should the archetype demonstrate one SSE endpoint" question:

- **The endpoint itself is already preset-mediated and env-gated.** `APPKIT_REALTIME=on` mounts `GET /events` with heartbeat, dedup machinery, and graceful drain, with zero template lines; that is strictly better than a build-tag-gated `internal/realtimedemo` skeleton because the skeleton pattern exists for weight the DEFAULT binary must not carry (cqrs needs DSN, config, `Close` wiring, `internal/events/events.go:29-40`), while the realtime leg needs only an env var. The remaining adopter gap is two lines of knowledge, not code: set `APPKIT_REALTIME=on` (or `RealtimeConfig{Enabled: true}`) and take the hub from `RealtimeConfig.Hub` (`preset/config.go:140-142`) to broadcast. A template demo file would freeze a broadcast-domain opinion (what event? what payload?) the archetype deliberately lacks.
- **What belongs where instead:** the demonstration belongs in the preset's example (`preset/example/main.go` currently has zero realtime content, verified by grep) plus a README posture line pairing the leg with `NoTimeout` `[PRESET-UPSTREAM]`; the template's job is at most one docs paragraph in its README pointing at the env flag, the hub out-field, and the WriteTimeout caveat `[TEMPLATE, docs-only]`.
- **Should the template switch the leg on? No.** With no domain there is no broadcast source; an always-mounted idle `/events` endpoint would be pure surface. Keep off (matches the go-appkit report's "off-by-default is right for an archetype", inventory row for the realtime leg). The dashboard spine already exercises go-sse in the default binary, so the template is not shipping an unexercised dependency either.
- **Stay out:** ssetest as a template test dependency (see below), sseparse (nothing server-side parses SSE), client-side `Dial` (does not exist yet, ROADMAP §2) .

## Risks

- **30s WriteTimeout (verified, see Gaps #1):** the template's default binary degrades its dashboard live view today, and the documented `APPKIT_REALTIME=on` flag yields 30s-dying streams. Cross-report agreement: go-appkit.md Gaps #6 and Risks state the same finding for the realtime leg; this audit additionally surfaces `go-appkit/health/doc.go:124-129`, which documents the spine-side instance the template already ships. Both reports route the fix `[PRESET-UPSTREAM]` (plus a `[LIB-UPSTREAM]` doc note here).
- **Default CORS `*` on the realtime leg** (`realtime/handler.go:21`): flipping the env flag exposes a cross-origin-readable event stream; go-sse's Security Practices (README:383-391) correctly push authentication to the caller, but the preset's env-grammar docs do not repeat it. Adopter-side concern, worth a preset README line `[PRESET-UPSTREAM]`.
- **Silent event loss without a store:** the drop-on-full policy plus the preset's storeless default hub means a slow `/events` consumer loses events with no recovery path until the next broadcast; the dashboard is immune by its full-state patch invariant, the realtime leg is not. Mitigated by Gaps #2.
- **No deprecated or misused APIs found** in anything the template mediates: the pinned v0.6.2 already contains the heartbeat-after-Close fix, the short-write contract fix, and the request-context-cancel hardening (CHANGELOG [0.6.1] Fixed). The template's own code has no go-sse surface to misuse.
